# Лабораторная работа №6 — Разработка серверной части приложения

**Модуль:** Разработка web-приложений. **Предметная область:** EventManager — система управления мероприятиями.

## Цель
Освоить PHP 8.2+, структуру MVC, маршрутизацию HTTP-запросов, контроллеры, HTML-представления и сохранение данных в JSON-файлах.

## Запуск

```bash
cd lab6/src
php -v
php -S localhost:8000 -t public
```

Открыть http://localhost:8000. **GitHub Pages не выполняет PHP**, поэтому для этой лабораторной нужен локальный PHP-сервер. Расширение `mbstring` не требуется; достаточно стандартных расширений PHP `json` и `pcre`.

## Структура

- `src/public/` — единственная публичная папка: точка входа `index.php`, CSS.
- `src/app/Core/` — `Router`: регистрация, сопоставление URL, вызов обработчика, 404/405.
- `src/app/Controllers/` — `HomeController`, `EventController`, `VenueController`.
- `src/app/Models/` — `EventRepository`, `VenueRepository`, общий `JsonRepository`.
- `src/app/Views/` — HTML-шаблоны с экранированием через `e()`.
- `src/routes/web.php` — таблица маршрутов.
- `src/config/app.php` — название системы.
- `src/storage/` — данные мероприятий и площадок в JSON.
- `docs/` — API, проверка, контрольные вопросы.
- `images/` — иллюстрации работы интерфейса и HTTP-ответов.

## Реализованная логика

Единая точка входа подключает автозагрузку, помощники и маршруты, затем передаёт запрос маршрутизатору. Маршрутизатор сопоставляет метод и URL (включая `{id}`), вызывает контроллер или показывает 404. При совпадении URL с неподдерживаемым методом возвращает 405.

`HomeController` подсчитывает мероприятия по статусам и число площадок. `EventController` отображает список с фильтром, карточку, форму создания, проверяет данные (422), сохраняет их в `events.json`, перенаправляет после успешного создания (302) и удаляет мероприятия. `VenueController` показывает список площадок и связанные мероприятия. После успешного изменения выводится одноразовое сообщение через сессию.

## Предметная область

| Параметр | Значение |
|---|---|
| Основная сущность | Мероприятие (`event / events`) |
| Связанная сущность | Площадка (`venue / venues`) |
| Поля мероприятия | `id`, `venue_id`, `title`, `date`, `status`, `capacity`, `description` |
| Статусы | `draft`, `published`, `completed` |
| Поля площадки | `id`, `name`, `address`, `capacity` |

Вместо примера «задачи и проекты» созданы мероприятия и площадки; переименованы контроллеры, модели, шаблоны, маршруты и JSON-файлы. Старые URL `/tasks` и `/projects` отсутствуют и возвращают 404. Роутер и автозагрузка не зависят от предметной области.

## Безопасность

Введённые значения проверяются на сервере. Данные выводятся через `htmlspecialchars` в `e()`, что снижает риск XSS. Каталог `storage` находится вне публичной папки. Для учебного проекта авторизация и CSRF-защита не предусмотрены; для реального развёртывания они обязательны.
