# Контрольные вопросы

1. При синхронном выполнении ответ ждёт окончания операции. Асинхронный ответ подтверждает постановку, результат появляется позже и требует отдельного процесса и проверки состояния.
2. Уведомление руководителя и экспорт CSV подходят для фона. Проверка токена и фиксация нового статуса должны закончиться до ответа, чтобы API мог вернуть корректный HTTP-результат.
3. Производитель — API EventManager. Очереди — структуры Redis. Воркер резервирует сообщение и запускает обработчик по типу.
4. `RPOP` сразу удаляет сообщение. `BLMOVE` перемещает его в рабочий список атомарно, сохраняя возможность повторить при сбое.
5. ACK удаляет успешную задачу из `working`. Без ACK при восстановлении она может выполниться ещё раз.
6. SIGKILL прекращает обработку, но резерв остаётся в Redis. Новый воркер получает блокировку и возвращает резерв в `ready` командой `LMOVE`.
7. Паузы в 2 и 4 секунды дают зависимостям время восстановиться. После третьей ошибки задача с причиной остаётся в `dead` для разбора.
8. At-least-once допускает повтор, если процесс прервался после выполнения, но до ACK, или если передача outbox повторилась.
9. Идемпотентная операция при повторе с тем же идентификатором сохраняет тот же прикладной результат. Уведомления уникальны по паре «UUID задачи, ID адресата».
10. В задачу кладут идентификаторы и минимальный снимок значимых параметров. Весь объект увеличивает очередь, может содержать лишние данные и устаревает.
11. HTTP 202 означает, что запрос принят для обработки. `Location` указывает, где запрашивать состояние. При `done` появится ссылка на скачивание.
12. CSV по-прежнему требует выборки и записи строк. API возвращает подтверждение раньше, потому что вынес эту работу в отдельный процесс.
13. API фиксирует задачу и изменение в PostgreSQL. Если Redis недоступен, незавершённая публикация остаётся в outbox, которую воркер проверяет после восстановления.
14. Отдельные воркеры разгружают очереди и разделяют быстрые и долгие задачи. `BLMOVE` атомарно резервирует каждый элемент. Эта реализация дополнительно блокирует второй воркер той же очереди на одном хосте.
15. SIGTERM или Ctrl+C инициирует остановку после текущей задачи при наличии `pcntl`. Если завершение принудительное, восстановление опирается на рабочий список и идемпотентные обработчики.
