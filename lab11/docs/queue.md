# Устройство очереди

## Сообщение

```json
{
  "id": "ffa0bf25-644f-4def-8bc1-7e5dcba59ef8",
  "type": "notification",
  "payload": {
    "event_id": 1,
    "title": "Форум цифровых технологий",
    "old_status": "planned",
    "new_status": "completed",
    "actor_id": 2
  },
  "attempt": 0,
  "created_at": "2026-11-20T00:00:00+00:00"
}
```

Уведомление хранит снимок перехода и название, чтобы отразить фактическое изменение, даже если к моменту исполнения статус сменился снова. Отчёт передаёт только `request_id`. CSV охватывает данные на момент выполнения выборки, а не на момент заказа. Задача с ошибкой получает `last_error`.

## Жизненный цикл

| Состояние | Хранилище | Переход |
|---|---|---|
| Готовится к доставке | Таблица `job_outbox` | Вставка в транзакции с бизнес-данными. |
| Ожидает | Список `ready` | `LPUSH` из API или воркера. |
| В работе | Список `working` | `BLMOVE ready working RIGHT LEFT 1`. |
| Завершена | Результат в PostgreSQL или CSV | `LREM working` подтверждает задачу после записи результата. |
| Ожидает повтора | ZSET `delayed` | Lua удаляет резерв и сохраняет сообщение со временем следующей попытки. |
| Исчерпала попытки | Список `dead` | После третьей ошибки Lua переводит задачу с текстом ошибки. |

Воркер публикует строки outbox, переводит доступные по времени повторы в `ready` и ждёт задачу через `BLMOVE` с тайм-аутом в одну секунду. Пока одна задача ждёт повтора, другие могут обрабатываться. При старте `LMOVE` возвращает неподтверждённые задачи. Локальный `flock` разрешает один воркер на очередь для общего каталога `storage`. Разные очереди работают независимо.

## Надёжность и границы

- **At-least-once.** Если процесс умер после записи результата, но до подтверждения, задача будет повторена. Если приложение успело положить сообщение в Redis, но не подтвердило транзакцию удаления строки outbox, возможна повторная публикация с тем же UUID.
- **Идемпотентность.** В уведомлениях составной первичный ключ `(job_id, user_id)` и `ON CONFLICT DO NOTHING`. CSV пишется во временный файл и публикуется переименованием после успешной записи. Повтор обходит завершённую заявку. При сбое между переименованием и отметкой `done` следующий запуск перезапишет файл тем же именем и опубликует статус.
- **Перезапуск Redis.** Compose сохраняет очередь через AOF. Outbox защищает интервал до публикации. Удаление Redis-тома или потеря неподтверждённых на диске данных может уничтожить уже опубликованные задачи.
- **Ошибки CSV.** До исчерпания попыток заявка остаётся `processing`, а при окончательном отказе получает `failed` и безопасное сообщение. Необработанные детали видны оператору в `dead`.
- **Производственная эксплуатация.** Нужны Supervisor или контейнер с перезапуском, метрики длины и возраста очередей, оповещения по `dead`, очистка старых файлов, резервное копирование Redis и PostgreSQL и отдельная стратегия блокировок для нескольких хостов. Синхронный режим предназначен для сравнения задержек. В учебном опыте он выполняет обработчик после фиксации бизнес-изменения.
