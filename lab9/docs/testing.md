# План и результаты комплексного тестирования

Автоматические тесты: `php tests/api-tests.php`. Тесты выполняют HTTP-запросы и проверяют фактические коды ответов, формат данных и ограничения ролей. Перед тестированием: `php bin/reset-db.php`. **Приведённые ниже ответы — модельные примеры для учебной проверки контракта. Это не протокол фактического выполнения.**

## Проверки безопасности

| Проверка | Метод | Ожидаемый результат | Модельный результат (не проверен) |
|---|---|---|---|
| Пароли в БД | `SELECT email,password_hash FROM users` | Только bcrypt-хеши | Модель: ожидаемое поведение, не проверено |
| Нет хеша в API | POST /api/auth/login | Поле password_hash отсутствует | Модель: ожидаемое поведение, не проверено |
| Защита без токена | GET /api/events | 401 | Модель: ожидаемое поведение, не проверено |
| Роли проверяются сервером | DELETE с токеном editor | 403 | Модель: ожидаемое поведение, не проверено |
| Защита от XSS | Название с HTML-тегами | Отображение через textContent | Модель: ожидаемое поведение, не проверено |
| SQL-инъекция | `GET /api/events?q=%27%20OR%201%3D1--` | Значение трактуется как текст | Модель: ожидаемое поведение, не проверено |
| Отзыв токена | Logout и повторный GET | 401 | Модель: ожидаемое поведение, не проверено |

## Материалы подтверждения

В `images/` необходимо добавить не менее 6 скриншотов: вход, список, создание, изменение, ограничение прав, вывод автотестов. Скриншоты создаются при реальном запуске системы, не заменяются макетами.

## Модельный протокол HTTP-проверок (пример заполнения)

Следующие строки показывают ожидаемый формат протокола, **не являются выводом запущенных тестов**.

| Запрос | Предусловие | Пример ответа |
|---|---|---|
| `POST /api/auth/login` | Верные учебные учётные данные | `200`, JSON с `token`, `expires_at`, `user` без `password_hash` |
| `POST /api/auth/login` | Неверный пароль | `401`, `{"error":"Неверный email или пароль"}` |
| `GET /api/events` | Нет заголовка Authorization | `401`, JSON с описанием ошибки |
| `GET /api/events` | Действительный токен | `200`, JSON-массив мероприятий |
| `POST /api/events` | Неверные данные | `422`, JSON с полем `errors` |
| `DELETE /api/events/{id}` | Токен редактора | `403`, JSON с описанием запрета |
| `DELETE /api/events/{id}` | Токен руководителя | `204`, пустое тело |
| `GET /api/events` | PostgreSQL остановлен | `503`, JSON с описанием недоступности БД |

После реального запуска необходимо заменить модельные результаты фактическими кодами и ответами, приложить журнал `php tests/api-tests.php` и скриншоты.
